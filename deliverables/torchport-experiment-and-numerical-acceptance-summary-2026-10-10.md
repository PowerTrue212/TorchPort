# TorchPort 迁移实验与数值验收方案整理

整理日期：2026-10-10

> 本文整理用户提供的讨论记录，按最后一版方案归纳，保留方案演变、证据边界和待确认事项。文中的实验数字来自原文，本次未复核原始 JSON 或运行实验。原文有部分句子截断，无法恢复的内容不作补写。本文不替代已冻结的正式协议。

## 1. 当前方向与工作顺序

本轮要回答两个问题：**TorchPort 是否帮助 Agent 完成真实迁移，以及怎样区分实现错误与正常数值差异。**

当前讨论收敛到以下方向：

- 迁移对照保留 **none / full 两组**；反馈粒度消融留到后续。
- 数值评价同时看 **E1：中间激活差异**和 **E2：最终任务效果**。
- E1 以 PyTorch 合法运行差异和独立测得的 Jittor 环境波动为参照。
- 候选自身的波动单独报告，不能用它放宽候选的验收门限。
- **先冻结判据，再开展正式迁移实验。**新实验只能检验规则，不能根据结果继续调门限。
- 小模型机制实验可以与环境准备并行；图表和证据随各阶段同步整理。

原冻结协议下的失败结果应保留。新判据必须作为新协议单独记录和评测，不能改写旧结论。

## 2. 迁移对照实验

### 2.1 两组回答什么

| 条件 | Agent 可用能力 | 比较目的 |
| --- | --- | --- |
| none | 正常浏览、搜索、编辑、执行和测试代码；不提供 oracle 对比结果 | 观察 Agent 独立迁移的效果 |
| full | 与 none 相同的代码能力，并可使用 TorchPort 全部验证与诊断能力 | 观察 TorchPort 带来的帮助 |

两组应只在 TorchPort 能力是否可用上不同，不能削弱其中一组的正常代码操作能力。oracle 指冻结条件下生成的 PyTorch 参考证据；none 组不可见，但实验结束后仍需用统一规则评价两组提交。

### 2.2 实验设置与未定项

| 项目 | 整理后的设置 | 状态 |
| --- | --- | --- |
| 被测模型 | 原文建议 DeepSeek V4.1 flash 为主，后续可加入 Qwen Coder | 建议；具体版本需冻结 |
| 反馈条件 | none / full | 后续讨论已明确 |
| 仓库 | BiRefNet、VSCode-v2、PlantCamo | 原文计划 |
| 开发与标定 | CamoFormer 用于开发和校准，不计入正式迁移效果统计 | 原文要求 |
| 重复次数 | 原建议每个“仓库 × 条件”至少 3 次 | 尚需确认 |
| 固定项 | 初始 candidate、提示词、模型版本、硬件、Token、轮数、墙钟和 GPU 预算 | 正式运行前冻结 |
| 范围 | 本轮聚焦前向迁移；训练等价、梯度和微调拟排除 | 原文提出，未见明确确认 |

若沿用每格 3 次，两组、三个仓库共需 **2 × 3 × 3 = 18 次迁移**。按原文单次 1～2 小时的假设，合计约 18～36 小时；实际 GPU 占用和并发预算还需单独估计。原先的 36 次对应四组方案，已不适用于当前设计。

原建议先用 BiRefNet 做试点。按两组方案调整后，可先做 **none / full 各 1 次**，确认工具、隔离、记录和评测流程能够闭环。

### 2.3 应报告的指标

- **结果：**结构与参数检查、E1 中间数值评价、E2 全测试集任务效果，分别报告。
- **投入：**用时、Token、Logical Query Cost、Physical Evaluation Cost。
- **失败：**失败类型和可追溯证据；首次越界位置不直接写成已确认根因。

Logical Query Cost 记录 `evaluate`、`verify`、`trace` 的调用次数、分工具计数和唯一 candidate 数；Physical Evaluation Cost 记录实际执行次数、进程墙钟时间和 CUDA 配置进程墙钟时间。两者分开统计。

## 3. 数值验收：以最后描述的 v3 为准

### 3.1 为什么需要实测参照

同一数学模型在不同精度、硬件或计算顺序下，可能产生不同的浮点结果。不同层的数值量级和误差传播也不同，固定容差可能放过小错误，也可能拒绝正常的后端差异。

讨论提出的基本思路是：**先测原模型在合法运行条件下会差多少，再用这个尺度判断迁移差异。**这提供了评价依据，但仍需负对照和真实任务验证，不能据此直接认定实现正确。

### 3.2 E1：整网真实激活的相对误差

E1 使用真实权重、真实图像，比较整网前向过程中可对应的中间激活。每层定义：

```text
rel(T, R) = ‖T − R‖₂ / ‖R‖₂
```

- `R`：PyTorch 参考运行，FP32，关闭 TF32。
- `T`：Jittor 候选的一次运行。
- `‖·‖₂`：整个张量的 L2 范数。

**PyTorch 差异 D：**保持模型、权重和待比较样本不变，采用不同合法运行方式，测各运行之间的最大相对差异。原文列举 cuDNN benchmark、FP64、CPU、channels_last，以及 batch size 为 2 且加入其他样本。每层包括参考运行在内，取所有运行两两比较的最大值。

这些变体是否保持任务语义，需要按模型确认。两两比较的归一化方向、参考张量范数为零时的处理，原文未明确。

**独立环境波动 N_env：**在同一 Jittor 环境中，用随机数据单独运行卷积、矩阵乘、LayerNorm、softmax、全局池化、GroupNorm 等算子。每个算子重复 5 次，取运行间最大相对差异。全局池化输入采用 source 模型中最大的对应形状。该测量不读取候选代码。

原文报告的 3080 Ti 测量为：

| 算子 | 运行间相对差异 |
| --- | ---: |
| 矩阵乘、LayerNorm、softmax | 测得为 0 |
| 卷积 | 约 1.8e-7 |
| 全局池化、全局求和 | 约 2e-6 |

整网 E1 使用这些算子的全局最大值作为 `N_env`。测得为 0 只描述此次测量，不能推广到所有输入或环境。

**候选判定：**候选重复运行 3 次，每层取最差一次，再取所有参与比较层的最大比值：

```text
ratio_layer = max_i rel(T_i, R) / max(D_layer, N_env)
ratio_max   = max_layer ratio_layer
```

候选自身的重复运行差异只列入报告，不参与扩大分母。

| ratio_max | 原文最后描述的结论 |
| --- | --- |
| ≤ 2 | E1 通过 |
| > 2 且 ≤ 4 | E1 不算通过，但允许提交，最终结合任务指标评价 |
| > 4 | E1 失败 |

这里把原文“2 到 4”整理为 `> 2 且 ≤ 4`，避免与“≤ 2 通过”重叠；正式协议需明确边界。

### 3.3 E2：最终任务效果

E2 使用真实完整 checkpoint 和全测试集，比较：

- 数据集指标：S、wF、E、MAE。
- 逐图预测差异。
- 必要时同时报告 logit、sigmoid 输出、量化图像，避免不同输出口径混用。

前期方案建议以 PyTorch 合法变体之间的指标差异作为 E2 包络，即“观测到的最大合法差异”。但最后一段没有给出完整 E2 门限、重复运行方式，以及 E1 灰区与 E2 如何形成最终 verdict，正式评测前必须补齐。

普通验收的最终结果仍应由 `verify` 给出；trace、模块隔离和错误定位提供诊断证据。

### 3.4 方案如何演变

| 阶段 | 主要办法 | 后续调整 |
| --- | --- | --- |
| 早期噪声标定 | 按 source 噪声乘 k，并加绝对误差项 | 讨论质疑倍数的依据及跨张量量级适用性 |
| 中期提案 | 去掉倍数，直接使用合法变体差异包络，并考虑 target 波动 | 后续明确波动必须独立于候选 |
| 原文所称 v2 | 用候选自身波动 N，门限为 D + N | 候选越不稳定，门限越宽；只看首次运行也会受运行顺序影响 |
| 原文所称 v3 | 用独立 N_env，比较三次运行的最差误差，并采用 2 / 4 分档 | 当前最后描述的方案；仍有覆盖和标定局限 |

因此，“完全去掉 k”是中间提案。最后版本仍包含 2 和 4 两条经验门限，不能概括为完全没有倍数或经验参数。

## 4. 已有证据与解释边界

### 4.1 七个候选的标定结果

以下按原文列出，未复核原始记录：

| 候选 | 原文描述 | E1 最大比值 |

| CamoFormer | 已知正确候选，任务指标接近 PyTorch | 0.65 |
| PlantCamo 修正版 | 已知正确候选，任务指标接近 PyTorch | 1.97 |
| BiRefNet | 已知正确候选，任务指标接近 PyTorch | 2.99；另两次复验为 3.10、2.86 |
| PlantCamo Agent 原版 | 17 处 eps 写反 | 11.1 |

2 / 4 门限是在看过这七个候选后选定的，属于开发期经验标定，不能把这些候选再当作独立证据证明门限普适。后续新仓库只能检验已冻结门限。

BiRefNet 的复验说明，以 3 为单一判定线可能发生边界跳动。按最后的 2 / 4 分档，它落在允许提交区，不能写成 E1 通过。

### 4.2 小模型实验

原文记录产物位于 `docs/evidence/precision_small/`，含脚本、`results.json`、6 张图和 README，CPU 运行约 14 秒。原报告明确说明数字尚未逐项核对。

| 实验 | 原文报告结果 | 可以支持的解释 |
| --- | --- | --- |
| A：加法顺序 | 相对 FP64 的误差为 1.4e-7～1.1e-6，没有哪种顺序总是更准 | 仅改变求和顺序就能产生舍入差异，不需要 GPU |
| B：权重 × 输入对照 | 16 个实验格子的实现差异 / 噪声包络比值为 0.8～1.25；末层增益跨 18 个数量级 | 在该实验中，实现差异与自身噪声随网络敏感度共同变化 |
| C：输出口径 | logit 差为 3.5e-7～3.8e-6；量化为 uint8 后差异为 0，预测和准确率一致 | 后处理可能压缩或消除可见差异 |
| D：错误与噪声 | 三个错误超出包络 15～3e6 倍；固定容差 1e-4 漏掉训练权重下的 ln_eps | 该实验中，固定容差与噪声参照的检错表现不同 |

**“训练权重一定减少误差放大”没有得到支持。**训练权重的末层增益高于 Xavier 初始化，仅低于刻意放大的初始化。不能把随机权重与真实权重的差别简单解释成训练抑制误差。

小实验采用确定性的计算顺序变体，没有建模 Jittor 的运行间不确定性。浮点非结合律可以解释顺序差异，但不意味着固定运行条件必然不确定。小模型结果不能替代 CamoFormer 的真实模型验证。

### 4.3 需要补齐的同口径对照

此前比较混入了两个变化：随机权重与训练权重使用的输入不同，比较的输出阶段也不同。因此，随机网络的 logit 最大差 1.03 与真实网络量化图像最大差 1/255 不能直接比较。

建议在同一 GPU、同一误差定义下完成：

| 权重 / 输入 | 随机输入 | 真实图像 |
| --- | --- | --- |
| 随机权重 | ① | ② |
| 训练权重 | ③ | ④ |

每格同时测 Jittor 与参考的逐层激活差异、PyTorch 合法变体差异，并分别观察 logit、sigmoid、量化图像和任务指标。① 对比 ③ 隔离权重影响，① 对比 ② 隔离输入影响。

若实现差异与 source 噪声同步放大，可以支持网络敏感度的解释；这本身不能排除迁移错误，还需负对照与独立验证。

## 5. 已知局限与待核实事项

1. **全局 N_env 可能盖住小错误。**原文称 VSCode-v2 的 561 层中有 550 层由 N_env 主导。此时每层判据主要受同一个环境底线控制。
2. **单算子波动不能完整描述整网传播。**原文称 BiRefNet 中 Jittor 误差经 BN 放大约 7 倍，PyTorch 变体差异放大约 2.5 倍；对应句子有截断，具体测量链需查原始证据。
3. **覆盖不完整。**E1 只使用一张输入图；参与比较层占 51%～94%；名称无法对应的层未参与；大张量采用压缩估计，不能写成完整逐元素验证。
4. **E1 与 E2 不能互相替代。**E1 通过不证明实现正确；任务指标一致也不证明实现正确。原文称 PlantCamo 的 eps 错误只使任务指标相差约 2e-7，却能被逐层比较发现。
5. **标定集与正式评测集可能重叠。**BiRefNet、PlantCamo 既在迁移仓库计划中，又用于选择门限。需明确开发与独立评测边界，不能继续称它们完全未参与标定。
6. **数值根因需要源码证据。**最后一段将卷积、全局求和和池化波动归因于原子加法，但未附源码位置；项目入口仍把源码级确认列为未完成。报告中宜先记为待核实的解释。
7. **两项表述需修正。**“正确实现最大比值不超过 3”与 BiRefNet 复验 3.10 不一致；“去掉 k”与最后的 2 / 4 门限也属于不同阶段，不能同时作为当前结论。
8. **正式规则仍缺细节。**需明确 E2 门限、E1 灰区处理、零分母、压缩误差、层匹配及覆盖不足时的处置，并绑定硬件、精度设置和协议版本。

### 验收与定位采用不同输入

整网 E1 中，每层接收 Jittor 上游输出，包含累计误差；原文使用全局 N_env。

定位时，把对应模块单独拿出，输入 source 记录的真实局部输入，以减少上游差异的干扰。这时按算子类型取环境波动：例如 LayerNorm 使用测得的 0，卷积使用卷积的测量值。若仍统一用约 2e-6 的全局值，小的 LayerNorm eps 错误可能被盖住。

原文最后一句截断，无法确认具体定位结果。模块隔离用于诊断，不能替代整网验收或任务效果验证。
