## 建议步骤

1. **环境与依赖**：确认两个 smoke；装 FNO 依赖；记录环境版本 JSON（参考
   `lightgcn-v1/record_3080ti_env.py`）。
2. **源端 pilot 复跑两次**：`probe_source_pilot.py`，必须关 TF32、开确定性算法、设
   `CUBLAS_WORKSPACE_CONFIG=:4096:8`。确认两次逐位一致。loss 与 V100 的 `0.29315555` 不同是正常的，
   照实记录。
3. **Jittor FFT 探针复跑**：`probe_jittor_fft.py`。1.3.11 没有公开 `jt.fft`，只有实/虚成对的
   `jt.nn._fft2`。FNO 需要 `rfft2`/`irfft2` 和复数权重，这是最难的部分；先确认前向、逆变换和梯度。
4. **训练 TaskSpec 与 source oracle**：默认设定（用户未改动）
   - 5 步、batch 2、Darcy 训练集前 10 条按固定顺序切 5 个 batch，随机初始化权重固定存成 NPZ；
   - 原 pilot 配置：`n_modes=(4,4)`、hidden 8、2 层、Adam lr 1e-3、MSE；
   - 2,209 个参数，**逐参数比较，不用 sketch**；
   - source adapter 放 `experiments/p2/fno-v1/`，形式参照
     `simcse-bert-base-v1/sup_train_source_entry.py` 和 `lightgcn-v1/train_source_adapter.py`；
   - 用 `profile=train-step` 建 FP32/FP64/alt oracle。注意 FP64 路径：若源码某处强制 FP32
     （CLIP 的 LayerNorm 就是例子），只在受控 adapter 里给 FP64 分支补，FP32 分支不动。
5. **控制端 Jittor 参考**：手写谱卷积，放 `controller/`（不进 Agent 工作区）。先过现行
   `train-step` 规则；不通过时先查重复波动，再查实现，不要调容差凑通过。
6. **校准**（做法照抄 LightGCN 3080 Ti，见 `lightgcn-v1/train-ckpt-five-step-3080ti-20261102.md`）：
   - 参考至少 11 次独立运行，建固定目标重复基数（`simcse-bert-base-v1/loo_repeat_baseline.py`），
     做留一检验，零误拒才算过；
   - 显式负对照至少三个：lr ×1.01、截断模式数 4→3、少一层（或 hidden 改一个），全部要检出；
   - 用 `make_pilot_task.py` 生成带 `train_envelope=train-repeat-envelope-v1-pilot` 的 TaskSpec，
     再跑两次新增参考的隐藏 `verify` 确认通过。
7. **任务指标**：source 按固定 seed 训练若干 epoch 得 checkpoint，在 `darcy_test_16` 上算相对 L2；
   Jittor 参考用同一权重重放，逐样本比较输出，再加一个负对照证明只看指标不够。
8. **结论文档**：写 `experiments/p2/fno-v1/4090-pilot-20261102.md`，格式参照 LightGCN 那两份：
   冻结材料和哈希、每步结果、证据归档路径（本地与远端 SHA256 一致）、仍未知的部分。全部标 `pilot_only`。
9. **准备 trial（不启动）**：参照 `lightgcn-v1/prepare_train_trial.py` 写 FNO 的版本和 prompt；
   `remote` 里 `python_config` 显式填 target 的 `python3.9-config`，Jittor 缓存按 series/condition 分开。

## 已经踩过的坑

- **python_config**：`remote_executor.py` 已修（`dd501ee`），但仍要显式写 target 自己的
  `python3.9-config`；否则 Jittor 编出 `cpython-312` 扩展，Python 3.9 报 `assert jit_utils.cc`。
  跑完查缓存里只有 `cpython-39` 的 `jit_utils_core*.so`。
- **trace 写满磁盘**：全量 `trace` 会记录每个模块和算子，SimCSE 64 句写了 19 GB。训练任务现在不暴露
  trace（`89bc29a`）；需要逐层数据时写只挂指定模块的诊断探针，先估算输出大小。
- **共用 oracle**：多个候选串行验收时共用一个 bound task 路径（`verify_train_reference.py --shared-task`），
  否则每次都重建 oracle。
- **Git Bash 改写 `/root/...` 参数**（变成 `E:/Git/root/...`）：远端路径参数用 PowerShell 传。
- **PowerShell 引号**：复杂远端命令写成 `.sh` 上传后执行，不要内联。
- **SSH 等待后台进程会超时**：长任务用 `nohup ... &` 启动，再另开连接查日志。
- **Jittor 内存损坏**（`double free`、`malloc(): memory corruption`）出现过，原样记录，不当作实现错误。
- 首次超限的位置不是已确认的根因。
