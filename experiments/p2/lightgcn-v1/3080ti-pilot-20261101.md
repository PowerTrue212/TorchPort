## 3080 Ti 实测结果

- source smoke：PyTorch `2.4.1+cu121`、NumPy `1.26.4`、3080 Ti `sm_86`，关闭 TF32 的 CUDA 矩阵乘输出有限。原始日志已拉回 `controller/train-3080ti-r1-pilot-raw/setup-logs/source-smoke.log`。默认 target smoke 因上述 cuDNN 8/9 不匹配而失败；`conv_opt=1` 的 Jittor `1.3.11.0` CUDA 矩阵乘 smoke 通过。原始失败与通过日志都保留，不把默认配置记为通过。
- 冻结任务 oracle digest：`72042cdf85c529645227e13b302a88775903ec73869ee54febc7eab0d1b09e37`。新 source oracle 的 FP32、FP64、alt、输入和状态 NPZ 均在证据归档中；两项初始权重完整加载。现行 `train-step` 包络下，控制端 r2 的隐藏 `verify` **通过**（10/10 张量、零超限）；学习率 `×1.01` 与正则 `×1.01` 两个负对照各自 `PARITY_FAILED`（9/10、5/10 超限）。这是 3080 Ti 新环境的结果，不更改 V100 的失败。
- 包含 oracle 在内的 source FP32 共 11 次，10 个输出中 8 个出现跨运行差异，最大 `2.1775258574052714e-7`；每项已观察 source peer 差都不超过该项 source FP32/FP64/alt 标定差。控制端参考共 11 次，10 个输出中 8 个出现 target peer 差，最大 `4.470348358154297e-8`。
